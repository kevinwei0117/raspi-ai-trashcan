### Part 1: Why the starting detection wasn't good enough

My mentor's `smart_bin.py` decided "something is on the tray" by comparing the **whole camera picture** with a saved empty picture:

```python
def frame_changed(frame, background, diff_threshold):
    diff = np.abs(frame.astype(np.int16) - background.astype(np.int16))
    return float(diff.mean()) > diff_threshold      # average change > 15 (out of 255)
```

When it saw a change, it sent the **entire 640 × 480 picture** to the AI:
```python
(label, confidence), = self.classifier.predict(Image.fromarray(frame))
```

**Problems with this in my real bin.** The reasons below are the ones I wrote in the new code's comments.

| # | Problem | Why it happens |
|---|---|---|
| 1 | **People and background clutter set it off** | The camera sees more than the tray. Anyone moving nearby changes the whole-picture average. |
| 2 | **The AI sees too much** | The whole picture includes the tray, the bin edges and the background, and the item is only a small part. The AI was trained on close-up photos of single items. |
| 3 | **Glare at the tray edges** | Light reflecting off the tray around the item confused the AI. |
| 4 | **The tray moves after every sort** | After the servos rotate and tilt, the "empty tray" picture is no longer accurate. |
| 5 | **It could get stuck** | If the saved empty picture drifted (lighting change), the program thought something was there forever. |
| 6 | **It could classify a moving hand** | The old code waited 3 changed frames but didn't check whether things had **stopped moving**. |

#### Fix 1: Only watch the tray (Region Of Interest)
The camera picture is **640 × 480**. I only look at a **360 × 360 square** in the middle (x 140–500, y 60–420), which is exactly centered on the tray:
```python
def _roi(self, frame):
    return frame[ROI_Y:ROI_Y + ROI_H, ROI_X:ROI_X + ROI_W]
```
**Result:** people and things outside the square are ignored. The square is 129,600 pixels instead of 307,200, so the code checks **58% fewer pixels**.

#### Fix 2: Find the item's outline instead of averaging the whole picture
New function `find_object_box()`:
```python
def find_object_box(roi_frame, roi_background, diff_threshold):
    diff = np.abs(roi_frame.astype(np.int16) - roi_background.astype(np.int16)).astype(np.uint8)
    gray_diff = diff.mean(axis=2).astype(np.uint8)                   # 1. how much each pixel changed
    _, mask = cv2.threshold(gray_diff, int(diff_threshold), 255,     # 2. changed > 35 → white, else black
                            cv2.THRESH_BINARY)
    mask = cv2.erode(mask, None, iterations=1)                       # 3. remove tiny specks (noise)
    mask = cv2.dilate(mask, None, iterations=2)                      # 4. fill small gaps in the item
    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL,          # 5. find outlines of white blobs
                                   cv2.CHAIN_APPROX_SIMPLE)
    if not contours:
        return None, 0.0
    largest = max(contours, key=cv2.contourArea)                     # 6. keep the biggest blob
    area = cv2.contourArea(largest)
    if area < MIN_BOX_AREA:                                          # 7. too small → not an item
        return None, area
    return cv2.boundingRect(largest), area                          # 8. rectangle (x, y, w, h)
```
**How it works, step by step:**
1. For each pixel, measure how different it is from the empty tray.
2. Pixels that changed by more than **35** (out of 255) become white. Everything else becomes black. This gives a black-and-white **mask** of what's new.
3. **Erode** shrinks the white areas slightly, which deletes single-pixel noise.
4. **Dilate** grows them back (twice), which fills holes inside the item.
5. **Contours** are the outlines of each white blob.
6. Keep the **largest** blob. That's the item.
7. If it's smaller than **6,000 pixels** (about 4.6% of the tray area), ignore it. It's just noise or a shadow.
8. Return the **bounding box**: the smallest rectangle around the item.

I raised `--diff-threshold` from **15 → 35**. The number now means something different: 15 was the **average** change across the whole picture, while 35 is the change needed for **each pixel** to count as part of the item.

#### Fix 3: Crop the item, and crop inward to avoid glare
New function `crop_with_padding()`:
```python
def crop_with_padding(roi_frame, box):
    x, y, w, h = box
    pad_x = int(w * BOX_PADDING_FRAC)        # -15% of width
    pad_y = int(h * BOX_PADDING_FRAC)        # -15% of height
    x0 = max(0, x - pad_x)
    y0 = max(0, y - pad_y)
    x1 = min(W, x + w + pad_x)
    y1 = min(H, y + h + pad_y)
    if x1 <= x0 or y1 <= y0:
        return roi_frame[y:y + h, x:x + w]   # item too small to shrink → use the original box
    return roi_frame[y0:y1, x0:x1]
```
- A **negative** padding (−15%) cuts **15% off each side** of the box. That removes the glowing glare around the item's edges and keeps the center of the item.
- **Safety check:** if the item is so small that cropping would leave nothing, it uses the uncropped box instead of sending an empty image (which would crash the AI).

Now the AI gets **only the item**:
```python
crop = crop_with_padding(roi_frame, box)
(label, confidence), = self.classifier.predict(Image.fromarray(crop))
```

#### Fix 4: Wait for the item to stop moving
```python
motion = mean_diff(roi_frame, self._previous_frame) > MOTION_THRESHOLD   # 6.0
self._previous_frame = roi_frame

if present and not motion:
    self._still_streak += 1        # item there AND still
elif not present:
    self._absent_streak += 1       # tray empty
else:
    self._still_streak = 0         # item there but moving (e.g. my hand) → reset
```
- `mean_diff()` compares **this** picture with the **previous** one. A big difference means something is still moving.
- It sorts only after the item is **present and still for 2 frames in a row** (`STABLE_FRAMES_REQUIRED = 2`).

#### Fix 5: Learn the empty tray properly, and re-learn after every sort
```python
def _init_background(self, roi_frame, warmup_seconds):
    ...
    if now - self._warmup_start < warmup_seconds:   # 1. wait (2 s at startup, 0.5 s after a sort)
        return False
    self._warmup_frames.append(roi_frame.astype(np.float32))
    if len(self._warmup_frames) < BACKGROUND_AVERAGE_FRAMES:   # 2. collect 10 pictures
        return False
    self._background = np.mean(self._warmup_frames[-BACKGROUND_AVERAGE_FRAMES:], axis=0)  # 3. average
    log("Background locked in. Ready.")
    return True
```
- **At startup:** wait **2 seconds** (the camera auto-adjusts its brightness at first), then average **10 pictures**. Averaging removes random camera noise.
- **After every sort:** the servos moved the tray, so it throws away the old picture and re-learns (after waiting **0.5 s** for the tray to settle):
  ```python
  self.sorter.sort(category)
  self._already_sorted = True
  self._start_background_capture()
  log("Re-locking background after sort...")
  ```
- I kept my mentor's slow update while the tray is empty (95% old + 5% new), so slow lighting changes are absorbed.

#### Fix 6: Never get stuck
```python
if present:
    if self._present_since is None:
        self._present_since = now
    elif (now - self._present_since) > STUCK_PRESENT_TIMEOUT:     # 4 seconds
        log("Present too long with no resolution - assuming drift, re-locking background.")
        self._start_background_capture()
```
If it thinks an item has been there for **more than 4 seconds** without sorting, the saved empty picture is probably wrong (for example, the room lighting changed). It re-learns the empty tray instead of staying stuck.

#### How the new detection loop works (summary)
```
1. Start → wait 2 s → average 10 pictures of the empty tray
2. Each new picture: cut out the 360×360 tray area
3. Find the biggest changed blob → is it bigger than 6,000 px?   no → tray empty
4. Is it still moving?                                            yes → wait
5. Present + still for 2 frames → crop 15% inward → ask the AI
6. "plastic 87%" → category_map → "Recycle" → servos sort it
7. Wait 0.5 s → re-learn the empty tray → back to step 2
   (if "present" lasts > 4 s without sorting → re-learn anyway)
```

### Part 4: Auto-start script (2:40 PM): `start_with_display.sh`

So the bin starts by itself on the bin's screen, without typing commands:
```bash
#!/bin/bash
sleep 5                                    # 1. wait for the desktop to finish loading
export DISPLAY=:0                          # 2. show windows on the Pi's own screen
cd ~/raspi-ai-trashcan                     # 3. go to the project folder
source .venv/bin/activate                  # 4. use the project's Python environment
python -m src.smart_bin > ~/smartbin.log 2>&1 &   # 5. start the bin in the background,
                                                  #    saving all messages to ~/smartbin.log
sleep 3                                    # 6. give the window time to appear
WID=$(xdotool search --name "Smart Recycling Bin" | head -1)   # 7. find the window
if [ -n "$WID" ]; then
  xdotool windowmove "$WID" 2560 0         # 8. move it to the second screen
  xdotool windowsize "$WID" 1024 600       # 9. resize it to fit the 7" screen
fi
wait                                       # 10. keep the script alive while the bin runs
```
- `> ~/smartbin.log 2>&1` saves normal output **and** errors to a log file I can read later.
- `&` runs the program in the background so the script can keep going.
- `xdotool` is a tool that controls windows from the command line. It's a backup in case `cv2.moveWindow` doesn't work.

### Part 5: Shutdown button test (7:06 PM): `test_button.py`

I'm adding a physical button so the bin can be shut down safely without a keyboard (pulling the power can corrupt the SD card). Before writing the real shutdown code, I wrote a **safe test** that only prints the button state:

```python
import time
import lgpio

GPIO_PIN = 21                                          # BCM pin 21 = physical pin 40

h = lgpio.gpiochip_open(0)                             # open the Pi's GPIO chip
lgpio.gpio_claim_input(h, GPIO_PIN, lgpio.SET_PULL_UP) # input with internal pull-up resistor

print("Watching pin 21. Press Ctrl+C to stop.")
try:
    while True:
        level = lgpio.gpio_read(h, GPIO_PIN)
        state = "PRESSED (low)" if level == 0 else "not pressed (high)"
        print(f"pin21 = {level}  ->  {state}")
        time.sleep(0.3)                                # check about 3 times per second
except KeyboardInterrupt:
    pass
finally:
    lgpio.gpiochip_close(h)                            # always release the pin
```

**How the button wiring works:**
- One leg of the button goes to **GPIO21 (pin 40)**, the other to **GND (pin 39)**.
- `SET_PULL_UP` turns on a resistor inside the Pi that holds the pin at **1 (high)** when the button isn't pressed.
- Pressing the button connects the pin to GND, so it reads **0 (low)**.
- So: **0 = pressed, 1 = not pressed.** This is called "active low".

**Why a separate test first:** if the wiring were wrong (for example, the pin always reading 0), a real shutdown script would turn off the Pi immediately every boot. Testing with print statements first is safe.

(Small mismatch I noticed later: the comment at the top says "every 0.2s", but the code waits `0.3` seconds.)

### Part 6: What I learned
1. **Computer vision basics:** thresholding, erode/dilate, contours and bounding boxes, which is how to find an object by what changed.
2. **Region of interest:** only processing the part of the picture that matters is more accurate **and** faster.
3. **AI input matters:** the model was trained on close-up single items, so giving it a tight crop of the item works better than the whole scene.
4. **Real machines need recovery logic:** re-learning after a sort and the 4-second stuck timeout keep the bin from getting confused.
5. **Test hardware safely first:** read the button before letting it shut anything down.

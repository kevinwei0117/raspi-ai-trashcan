### Part 2: What every file is, what it does, and how it works in my bin

#### `models/trashnet_mobilenet_v2.tflite`: the AI brain
- **What it is:** a trained neural network stored as one file, **2,719,744 bytes (2.7 MB)**.
- **What it does:** takes a picture and returns 6 scores, one per material.
- **How it works:**
  - It's **MobileNetV2**, Google's image-recognition network for phones and small computers.
  - It started from a version that already recognized 1,000 everyday objects (ImageNet), and was then **retrained on TrashNet**, a dataset of about 2,500 trash photos.
  - **Accuracy: 82.6%** on test photos it had never seen (source: `README.md`).
  - `.tflite` = TensorFlow Lite, a format built for small devices.
  - It is **quantized**: numbers are stored as 8-bit integers (0–255) instead of decimals, which makes it about 4× smaller and faster.
  - Input must be exactly **224 × 224 pixels** (source: `scripts/train_trashnet.py`, `IMG_SIZE = (224, 224)`).
- **In my bin:** runs once every time an item is placed on the tray.

#### `models/trashnet_labels.txt`: the answer list
```
cardboard
glass
metal
paper
plastic
trash
```
The AI only outputs numbers (for example, "score #5 is highest"). This file turns the position into a name: line 5 = `plastic`.

#### `src/smart_bin.py`: the main program, 205 lines
- **What it is:** the file I run to start the bin: `python -m src.smart_bin`
- **What it does:** starts the camera, AI and servos, watches the tray, and decides **when** to classify and sort.
- **How it works:** it runs **two threads (jobs) at the same time**:
  1. **Main loop:** grabs pictures nonstop and shows them on the screen with the AI's latest answer:
     ```python
     frame = np.array(self.camera.capture())
     text = f"{r['label']} ({r['confidence'] * 100:.0f}%) -> {r['bin']}"
     cv2.putText(display, text, (10, 30), cv2.FONT_HERSHEY_SIMPLEX, 0.7, color, 2)
     cv2.imshow("Smart Recycling Bin", display)
     ```
  2. **AI worker:** detects new items by comparing each picture with a saved picture of the empty tray:
     ```python
     def frame_changed(frame, background, diff_threshold):
         diff = np.abs(frame.astype(np.int16) - background.astype(np.int16))
         return float(diff.mean()) > diff_threshold    # default: 15 out of 255
     ```
     - If the picture stays changed for **3 frames in a row** (`STABLE_FRAMES_REQUIRED = 3`), it classifies and sorts.
     - While the tray is empty, it slowly updates the "empty tray" picture so lighting changes don't trigger it:
       ```python
       self._background = 0.95 * self._background + 0.05 * frame.astype(np.float32)
       ```
- **Settings** (command-line options):

  | Option | Default | Meaning |
  |---|---|---|
  | `--confidence-threshold` | 0.40 | Below 40% sure, use the safe bin |
  | `--diff-threshold` | 15.0 | How different the picture must be to count as "something is there" |
  | `--cooldown` | 1.5 s | Pause after each sort |
  | `--no-preview` | off | Run without the screen window |

#### `src/camera.py`: the eyes, 59 lines
- **What it does:** gives the program one simple command, `camera.capture()`, which returns a picture.
- **How it works:** it tries the **Pi Camera** first (`picamera2` library). If that isn't installed, it uses a **USB webcam** (OpenCV):
  ```python
  try:
      from picamera2 import Picamera2
      self._picam2 = Picamera2()
      ...
      return
  except ImportError:
      pass
  import cv2
  self._cv_capture = cv2.VideoCapture(0)
  ```
- **Resolution:** 640 × 480.
- **In my bin:** the Pi Camera mounted on top of the frame, pointing down at the tray.

#### `src/classifier.py`: talks to the AI, 65 lines
- **What it does:** loads the model and answers "what is this?" for one picture.
- **How it works, in 3 steps:**
  1. **Prepare the picture:** resize to 224 × 224 and turn it into numbers.
     ```python
     resized = image.convert("RGB").resize(tuple(self._input_size[::-1]))
     array = np.asarray(resized)
     ```
  2. **Run the neural network:**
     ```python
     self._interpreter.set_tensor(self._input_details["index"], tensor)
     self._interpreter.invoke()
     output = self._interpreter.get_tensor(self._output_details["index"])[0]
     ```
  3. **Convert the scores to percentages and pick the highest:**
     ```python
     output = (output.astype(np.float32) - zero_point) * scale
     top_indices = np.argsort(output)[-self.top_k:][::-1]
     return [(self._labels[i], float(output[i])) for i in top_indices]
     ```
- **Example output:** `[("plastic", 0.87)]` means 87% sure it's plastic.
- The **Interpreter** is the engine that runs `.tflite` files. It comes from the `tflite-runtime` package, which caused today's main problem (Part 3).

#### `src/category_map.py`: decides the bin, 26 lines
- **What it does:** turns the AI's **material** into a **physical bin**.
- **How it works:** a Python **dictionary** (lookup table). Anything not in the table goes to the default bin.
- **Mentor's version (4 bins):**
  ```python
  CATEGORIES = ("glass", "metal", "plastic", "other")
  _LABEL_TO_CATEGORY = {
      "glass": "glass", "metal": "metal", "plastic": "plastic",
      "cardboard": "other", "paper": "other", "trash": "other",
  }
  _DEFAULT_CATEGORY = "other"
  ```
- **In my bin:** this has to change. My bin has **2 sides**, not 4 (Part 4).

#### `src/servo_sorter.py`: moves the motors, 89 lines
- **What it does:** sorts the item using **2 servos**:
  - **Rotate servo, channel 8:** turns the platform so the correct bin is underneath.
  - **Tilt servo, channel 11:** tips the tray to drop the item.
- **How it works:** both servos plug into a **PCA9685 servo driver board**, which the Pi controls over I2C using `adafruit_servokit`:
  ```python
  from adafruit_servokit import ServoKit
  self._kit = ServoKit(channels=16)       # PCA9685 has 16 servo slots
  self._kit.servo[8].angle = 90           # move channel 8 to 90 degrees
  ```
- **Sort sequence:** rotate to bin → wait 1.0 s → tilt to drop → wait 1.3 s → tilt back → wait 0.4 s → rotate back → wait 0.8 s.
- **Mentor's settings:**
  - 4 rotate angles: glass 0°, metal 60°, plastic 120°, other 180°
  - A tilt offset (`TILT_OFFSET = 60`), because this tilt servo is physically flat at 30°, not 90°
- **Safety feature:** with no servo board connected (for example on a laptop), it prints what it would do instead of crashing.

#### `src/main.py` + `src/sorter.py`: the older test version
- A simpler version that classifies the whole camera picture every 1.5 s and lights an **LED** on GPIO pins 17 / 27 / 22 / 23.
- **In my bin:** not used. Useful for testing the AI without motors.

#### `scripts/train_trashnet.py`: the AI training recipe, 119 lines
- **What it does:** creates the `.tflite` model from TrashNet photos.
- **How it works:**
  1. Split the photos: 80% training / 20% testing (`validation_split=0.2`).
  2. Load MobileNetV2 with ImageNet knowledge and **freeze** it. Add a new final layer with 6 outputs.
  3. Train for **10 epochs**, with **augmentation** (random flip, rotation and zoom) for more variety.
  4. **Fine-tune:** unfreeze the last 30 layers and train **5 more epochs** at a very small learning rate (`1e-5`).
  5. Convert to `.tflite` with 8-bit quantization and save it, together with the labels file.
- **In my bin:** run once on a laptop (about 10–15 minutes). My mentor already did this, so I received the finished model.

#### `scripts/calibrate_servo.py`: the angle-finding tool, 55 lines
- Type an angle from 0 to 180, and the servo moves there. I use it to find where the tray is flat, where it drops, and where each bin lines up.

#### `requirements.txt` / `requirements-train.txt`: install lists
- `pip install -r requirements.txt` installs everything the bin needs:

  | Package | Used for |
  |---|---|
  | `tflite-runtime` | Running the AI model |
  | `numpy` | Math on pictures |
  | `Pillow` | Resizing pictures |
  | `opencv-python` | Image processing + the preview window |
  | `picamera2` | The Pi Camera |
  | `RPi.GPIO` | The Pi's pins |
  | `adafruit-circuitpython-servokit` | The PCA9685 servo board |

- `requirements-train.txt` adds the training-only packages.

#### `tests/`: automatic checks
- `test_category_map.py` and `test_smart_bin.py` check that the logic still works (for example, that `paper` maps to `other`). Run them with `pytest tests/`.

### Part 3: Problem: the AI engine would not install

**Symptom:** installing `requirements.txt` failed on the line
```
tflite-runtime==2.14.0; platform_machine == "aarch64" or platform_machine == "armv7l"
```

**Root cause:**
- My Pi runs **Python 3.13** on a **64-bit ARM (aarch64)** processor.
- **No `tflite-runtime` package is published for Python 3.13 on ARM**, so pip had nothing to install.
- Without it, `classifier.py` cannot load the model, and the whole program fails.

**Fix (1:24–1:26 PM):** switched to **LiteRT** (`ai-edge-litert`), Google's replacement for `tflite-runtime`, which supports my Pi.

`src/classifier.py`, **before** (mentor's):
```python
try:
    from tflite_runtime.interpreter import Interpreter
except ImportError:  # dev machines without tflite-runtime installed
    from tensorflow.lite.python.interpreter import Interpreter
```

**After** (mine). It tries 3 AI engines in order and uses whichever is installed:
```python
try:
     from tflite_runtime.interpreter import Interpreter
except ImportError:
    try:
        from ai_edge_litert.interpreter import Interpreter
    except ImportError:  # dev machines without either installed
        from tensorflow.lite.python.interpreter import Interpreter
```

`requirements.txt`: I commented out the line that broke installs:
```diff
-tflite-runtime==2.14.0; platform_machine == "aarch64" or platform_machine == "armv7l"
+#tflite-runtime==2.14.0; platform_machine == "aarch64" or platform_machine == "armv7l"
```

Environment setup and installing LiteRT **(reconstructed)**. The `.venv` folder is timestamped 1:33 PM:
```bash
cd ~/raspi-ai-trashcan
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install ai-edge-litert
```

**Result:** `classifier.py` can now load the AI model on my Pi.

### Part 4: Started adapting the code to my 2-bin design (1:38 PM)

My bin has **2 sides (Recycle / Trash)**, but the starting code sorts into **4 bins**. I rewrote `category_map.py`:

```python
CATEGORIES = ("Recycle", "Trash")

_LABEL_TO_CATEGORY = {
    "glass": "Recycle",
    "metal": "Recycle",
    "plastic": "Recycle",
    "cardboard": "Recycle",   # mentor's version: "other"
    "paper": "Recycle",       # mentor's version: "other"

```

**Design decisions:**
1. **Cardboard and paper are recyclable**, so they go to Recycle. In the mentor's version they went to "other".
2. **Unknown labels go to Trash.** One wrong item in recycling can contaminate the whole batch, so Trash is the safer default.

### Part 5: What I learned
1. **How an AI project is organized:** model file → labels → camera → classifier → decision logic → hardware control. Each file has one job.
2. **A classifier always picks one of its labels.** It can't say "nothing is there", so the main program has to detect items separately, by comparing pictures.
3. **Packages depend on the Python version and processor type.** A package that works on a laptop may not exist for a Raspberry Pi.
4. **Fallback imports** (`try` → `except ImportError` → try the next option) make code work on more machines.

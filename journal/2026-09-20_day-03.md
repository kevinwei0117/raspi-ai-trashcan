### Change 1: Photo mode → video (preview) mode
```diff
-config = self._picam2.create_still_configuration(
+config = self._picam2.create_preview_configuration(
```
- **Still configuration** is made for taking single high-quality photos. It's slower between pictures.
- **Preview configuration** is made for a continuous video stream. My bin grabs pictures nonstop (the screen preview plus the detection loop), so preview mode is the right one: faster and smoother.

### Change 2: Color format RGB888 → BGR888
```diff
-main={"size": self._resolution, "format": "RGB888"}
+main={"size": self._resolution, "format": "BGR888"}
```
- Every pixel has 3 numbers: red, green, blue. Different libraries store them in **different orders**.
- In `picamera2`, the format names are confusing: `"RGB888"` actually gives the pixels in **B-G-R** order in Python, and `"BGR888"` gives **R-G-B** order.
- The rest of my code (`Image.fromarray(...)` and the AI) expects **R-G-B**. With the old setting, **red and blue were swapped**, so a blue bottle looked orange to the AI. The AI was trained on normal-colored photos, so wrong colors make its guesses worse.
- `BGR888` gives the R-G-B order the AI expects.
- **(Reconstructed)** I don't have a record of the exact moment I noticed the colors were wrong. The most likely sign was the preview window showing swapped colors.

### Change 3: Backup camera if the Pi Camera fails
**Before** (mentor's): it only fell back to a webcam if the `picamera2` **library** wasn't installed:
```python
except ImportError:
    pass
```
**After** (mine): it falls back on **any** problem, including broken hardware, and prints the reason:
```python
except Exception as e:
    print(f"[camera] Pi Camera Module unavailable ({type(e).__name__}: {e}), "
          f"falling back to USB webcam...")
```
and confirms which camera it ended up using:
```python
print("[camera] Using USB webcam.")
```
- `ImportError` only happens when a library is missing. On my Pi the library **is** installed, so if the camera itself or its ribbon cable had a problem, the old code would **crash** instead of switching cameras.
- The comment I added at the top of the file explains why: *"if it's installed but fails to find actual camera hardware (e.g. a damaged CSI port/cable), falls back to a USB webcam via OpenCV."*
- **CSI** = Camera Serial Interface, the flat ribbon-cable port the Pi Camera plugs into. These ribbon cables are fragile.

### How the camera code works now
```
Start → try the Pi Camera (preview mode, 640×480, BGR888)
          ├─ works → use it
          └─ ANY error → print why → try USB webcam #0
                                       ├─ works → print "Using USB webcam."
                                       └─ fails → stop with "No camera available"
```

### What I learned
1. **Photo mode vs. video mode:** use the mode that matches how the camera is used.
2. **Color channel order (RGB vs. BGR)** differs between libraries. Getting it wrong doesn't crash anything, but it silently makes the AI worse.
3. **Catch the right errors:** `except ImportError` only covers missing libraries. `except Exception` also covers hardware failures.
4. **Print what's happening:** the new messages tell me which camera is in use without guessing.
